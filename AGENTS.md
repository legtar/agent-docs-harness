# AGENTS.md — харнес для красивых DOCX/PDF и аккуратных правок

Этот файл — единые правила для любого агента в этой папке (Claude Code, Codex, Cursor, Gemini…).
`CLAUDE.md` просто импортирует его. Меняешь правила — меняй здесь.

## Главный закон

**Документ не отдаётся пользователю, пока `python tools/qa.py <файл>` не вернул PASS и ты
не посмотрел глазами `out/qa/new/<файл>/sheet.png`** (а при сомнениях — отдельные `page-NNN.png`).
QA ловит то, что ломает вёрстку: наложение текста, вылезание за поля, оторванные строки таблиц,
висячие заголовки, пустые страницы и пустое оглавление, подмену и невстроенность шрифтов,
«тофу» (нет глифа), забытые плейсхолдеры, а при правке — сдвиг вёрстки на страницах, где текст не менялся.
Глаза ловят остальное (эстетику, ритм, смысл). Нужны оба шага.

Цикл: **сгенерировал/поправил → qa.py → посмотрел sheet.png → исправил → снова qa.py**.
Ошибка не отпускается со словами «это мелочь»: ERROR = не готово.

## Карта

| Путь | Что |
|---|---|
| `tools/render.py FILE` | любой .docx/.typ/.html/.pdf → PDF + `page-NNN.png` + `sheet.png` (все страницы на одной картинке) |
| `tools/qa.py FILE [--original ORIG] [--pages N] [--allow-reflow]` | гейт вёрстки; exit 1 при ERROR |
| `tools/docx_kit.py` | создание DOCX в нашем стиле: `reference.docx`, `new_document()`, `add_table()`, `add_toc()`, `md` → docx |
| `tools/docx_edit.py` | хирургические правки существующего DOCX: замена текста через границы run'ов, таблицы, track changes |
| `tools/pdf_edit.py` | точечная замена текста в PDF без исходника (тот же шрифт/размер/цвет, отказ при переполнении) |
| `tools/lo_export.py` | внутренний: DOCX→PDF через LibreOffice UNO с обновлением оглавления и полей |
| `templates/report.typ` | дизайн-система PDF (Typst): типографика, таблицы booktabs, колонтитулы, русская типографика |
| `templates/reference.docx` | дизайн-система DOCX (стили); пересобирается `python tools/docx_kit.py reference` |
| `fonts/` | PT Serif / PT Sans (OFL, полная кириллица) для Typst |
| `examples/report.typ` | минимальный пример отчёта |
| `tests/validate.py` | сквозная проверка харнеса на сложных документах; запускать после любых правок в `tools/`/`templates/` |
| `out/` | всё сгенерированное (можно удалять) |

Окружение (Windows): Python 3.12 + `python-docx lxml pymupdf pypdf pikepdf pdfplumber typst docxtpl weasyprint`,
LibreOffice (`C:\Program Files\LibreOffice`), pandoc (`%LOCALAPPDATA%\Pandoc`), adeu (`%USERPROFILE%\.local\bin\adeu.exe`).
Установка с нуля: `winget install -e --id TheDocumentFoundation.LibreOffice`, `winget install -e --id JohnMacFarlane.Pandoc`,
`pip install python-docx lxml pymupdf pypdf pikepdf pdfplumber typst docxtpl weasyprint`, `uv tool install adeu`.
Всегда ставь `PYTHONUTF8=1`, если выводишь кириллицу в консоль Windows (иначе cp1251 падает).

## Создание: правила, из-за которых вёрстка не едет

**Общие**
- Стиль задаётся токенами в одном месте (`TOKENS` в `docx_kit.py`, переменные в начале `report.typ`). В документах никакого прямого форматирования: ни шрифтов, ни размеров, ни цветов «по месту».
- Отступы делаются интервалами стилей. Пустые абзацы, пробелы, табы и ручные `\n` для вёрстки запрещены.
- Заголовки всегда держатся со следующим текстом: в DOCX `keep_with_next`, в Typst это поведение по умолчанию.
- Таблицы:
  - всегда на ширину колонки текста, с фиксированными ширинами колонок;
  - шапка повторяется на каждой странице, строки не рвутся между страницами;
  - числа выровнены вправо;
  - без вертикальных линий.
- Изображения ставятся inline (не плавающие), шириной не больше колонки, с подписью.
- Русская типографика: «ёлочки», длинное тире с пробелами, неразрывный пробел после коротких предлогов и между числом и единицей (`18 %`, `5 млн`). В Typst шаблон делает это сам. В DOCX пиши `\u00a0` руками там, где разрыв недопустим.

**DOCX** (документ откроют в чужом Word, поэтому вёрстка зависит от его машины):
- Только шрифты, которые есть в любом Office: Calibri, Cambria, Georgia, Arial, Times New Roman. Сейчас тело Calibri, заголовки Georgia. Шрифт не из этого списка — только со встраиванием, и QA должен пройти.
- Без автопереноса, выключка влево: перенос и выключка по ширине по-разному работают в Word и LibreOffice.
- Не набивай страницу «под завязку»: в чужом Word строка может сдвинуться. Большие разделы начинай с разрыва страницы (`page_break_before` в стиле H1), а не с пустых строк.
- Оглавление — только полем TOC (`add_toc` или `--toc`). Word обновит его при открытии, наш рендер обновляет его сам.
- Если внешний вид критичен (печать, подпись, отправка наружу), отдай DOCX **и** PDF.

**PDF (Typst)**
- Шрифты из `fonts/`, они встраиваются в файл, поэтому PDF выглядит одинаково везде.
- Таблица до 25 строк неразрывна. Длинная таблица разрывается, и если QA пишет «table starts at the page bottom», ставь `#pagebreak(weak: true)` перед ней.
- `#callout[...]` — выделенный блок. `figure(table(...), caption: [...])` — таблица с подписью сверху.

## Правки существующих документов: протокол

1. **Оригинал не трогаем никогда.** Результат пишется в новый файл (`name.v2.docx`). Инструменты отказываются писать поверх входа.
2. **Сначала разведка:**
   - `docx_edit.py IN --tables` — таблицы с индексами;
   - `--dry-run` — совпадения с контекстом;
   - `python tools/render.py IN` — как документ выглядит сейчас.
3. **Каждая правка должна совпасть ровно `count` раз** (по умолчанию 1). Иначе инструмент ничего не пишет и показывает ближайшие абзацы. Удлиняй фразу поиска, а не ослабляй проверку.
4. **Минимальный дифф:**
   - меняются только затронутые run'ы, их форматирование сохраняется;
   - остальные части ZIP копируются байт в байт;
   - XML не переформатировать;
   - `styles.xml`, `numbering.xml`, `settings.xml` не трогать.
5. **Проверка результата:** `python tools/qa.py OUT --original IN`. Ожидается:
   - `pages with text changes` — только те страницы, где правка;
   - без `layout moved` на остальных;
   - число страниц не изменилось. Если правка законно сдвигает текст (вставили абзац), добавь `--allow-reflow` и посмотри страницы глазами.
6. **Track changes** — когда пользователь будет ревьюить правки (договоры, отчёты для согласования): `--track "Имя"`. Валидатор встроенного docx-скилла (если есть): `python ~/.claude/skills/synced/*/docx/scripts/office/validate.py OUT --original IN --author "Имя"`.
7. **Отчёт пользователю:** что поменяно (дифф из qa.py), где (страницы), путь к `sheet.png`.

### docx_edit.py — блоки, текст, таблицы

Сначала посмотри структуру, потом опиши правки пакетом операций (ops.json).
```bash
python tools/docx_edit.py in.docx --blocks        # #индекс  H1/p/table  стиль  list  'текст'
python tools/docx_edit.py in.docx --tables        # таблицы: t / r / c индексы
python tools/docx_edit.py in.docx out.docx --ops ops.json --dry-run    # всё разрешилось? ничего не пишет
python tools/docx_edit.py in.docx out.docx --ops ops.json [--track "Claude"]
python tools/qa.py out.docx --original in.docx [--allow-reflow]
```
Адрес блока (`B`): уникальный фрагмент текста блока или `"#12"` из `--blocks`. Якоря разрешаются
после предыдущих операций, поэтому фрагменты текста надёжнее индексов. Таблица (`T`) задаётся индексом из `--tables` или фрагментом текста внутри неё.

| Операция | JSON |
|---|---|
| заменить фразу (во всех частях: тело, колонтитулы, сноски) | `{"op":"replace","find":"…","replace":"…","count":1}` |
| переписать абзац целиком | `{"op":"set_text","block":B,"text":"…"}` |
| вставить абзац(ы), заголовок, пункт списка | `{"op":"insert","after":B,"text":"…"}` / `"texts":[…]`, `"like":B`, `"style":"Heading 2"` |
| вставить таблицу | `{"op":"insert_table","after":B,"rows":[[шапка…],[…]],"like":T}` (без `like` — таблица в стиле дома) |
| удалить блок / диапазон | `{"op":"delete","block":B,"to":B}` |
| удалить раздел | `{"op":"delete_section","heading":B}` — заголовок и всё до следующего заголовка того же или старшего уровня |
| переместить блок / диапазон | `{"op":"move","block":B,"to":B,"after":B}` |
| разрыв страницы перед | `{"op":"page_break_before","block":B}` (для таблицы — перед её подписью) |
| ячейка / строка | `{"op":"cell","table":T,"row":R,"col":C,"text":"…"}`, `{"op":"add_row","table":T,"after":R,"values":[…]}`, `{"op":"del_row","table":T,"row":R}` |

Короткие флаги для одиночных правок: `--replace OLD NEW`, `--set-text B TEXT`, `--insert-after B TEXT [--like B]`,
`--delete B`, `--delete-section H`, `--page-break-before B`, `--cell T R C TEXT`, `--add-row T AFTER "a|b|c"`, `--del-row T R`.

**Как сохраняется оформление и шрифт**
- `replace` переписывает только реально изменившиеся символы: общий префикс и суффикс остаются нетронутыми. Слово, выделенное жирным внутри фразы, остаётся жирным, а редлайн получается минимальным. Новые символы берут формат соседнего run'а.
- `insert` / `set_text` берут свойства абзаца у `like` (стиль, нумерацию списка, интервалы) и формат первого run'а (шрифт, размер, цвет). Пункт списка, вставленный рядом с пунктом, продолжает нумерацию. Заголовок вставляй с `like` = существующий заголовок нужного уровня.
- `insert_table` с `like` клонирует свойства таблицы: ширины, границы, шапку из 1-й строки, тело из 2-й.
- `add_row` клонирует строку с её границами и форматом. `cell` сохраняет формат первого run'а ячейки.
- Клоны очищаются от paraId, закладок, якорей комментариев и старых ревизий, поэтому дублей ID не бывает.

**Гарантии**
- Любая неудачная операция отменяет весь пакет: ничего не записывается, выводится причина и ближайшие кандидаты.
- Неоднозначный якорь — это ошибка, а не «первое совпадение».
- Части ZIP, которые не менялись, копируются байт в байт.

**Ограничения**
- Совпадение `replace` не пересекает табы, разрывы, поля и картинки.
- Одна замена — внутри одного абзаца.
- Перемещение в режиме track changes записывается как удаление плюс вставка, а не как Word-move.
- Форматные правки (`page_break_before`) в track changes не попадают.

### adeu — редлайны с комментариями (MIT, github.com/dealfluence/adeu)
```bash
adeu extract in.docx                       # DOCX → Markdown для чтения моделью
adeu apply in.docx edits.json -o out.docx --author "Claude"
# edits.json: [{"type":"modify","target_text":"…","new_text":"…","comment":"почему"},
#              {"type":"insert_row","target_text":"текст строки","cells":["a","b"],"position":"below"}]
adeu diff a.docx b.docx
```
Если пакет правок не проходит проверку, adeu откатывает его целиком. После adeu тоже обязателен `qa.py --original`.

### pdf_edit.py
```bash
python tools/pdf_edit.py in.pdf out.pdf --replace "486,2" "491,7" [--count N] [--dry-run]
python tools/qa.py out.pdf --original in.pdf
```
Как работает:
- Старый текст удаляется редакцией: он не просто закрашен, а не извлекается.
- Картинки и векторная графика под ним сохраняются.
- Новый текст набирается встроенным шрифтом документа на той же базовой линии.

Когда отказывает:
- если в подмножестве шрифта нет нужных глифов;
- если новый текст шире старого. Тогда переформулируй короче или пересобери PDF из исходника.

## Что делать по сообщениям QA

| Сообщение | Исправление |
|---|---|
| `table starts at the page bottom` (DOCX) | `page_break_before` на подписи таблицы. LibreOffice игнорирует keep-with-next внутри таблиц, Word его соблюдает; разрыв работает одинаково в обоих |
| `table starts at the page bottom` (Typst) | `#pagebreak(weak: true)` перед таблицей |
| `overlapping text` | неразрывный блок не влез на страницу, отрицательные отступы или абсолютное позиционирование: найди и разреши разрыв |
| `content ends at NN% of the page` (WARN) | устаревший принудительный разрыв или перескочившая таблица/рисунок: убери разрыв или перестрой порядок |
| `font … not installed` / `fell back to` | смени шрифт на токенный или установи нужный; иначе вёрстка у получателя другая |
| `TOC is empty` | поле не обновлено: проверь, что рендер идёт через UNO (`lo_export.py`) |
| `layout moved` при правке | правка задела форматирование вне цели: смотри дифф и страницы; если сдвиг ожидаем — `--allow-reflow` |

## Известные ограничения
- DOCX рендерится через LibreOffice, а у получателя он откроется в Word. Разница бывает в долях строки, поэтому правила выше и оставляют запас. Точный рендер Word возможен только при установленном Word (`pip install docx2pdf`).
- Проверка разрывов таблиц видит разрыв только по повторённой шапке. Без шапки таблицу проверяют глаза.
- Проверка наложений игнорирует строки разной высоты (это формулы). Наложение формул проверяется глазами.
- `find_tables` на научных PDF иногда принимает рисунки за таблицы. Сверяйся с картинкой.

## Надёжность и объекты — обновление 1 октября 2026

- Перед передачей документа по-прежнему обязательны QA PASS и визуальный просмотр.
- Для создания по описанию сначала составь содержание, структуру и таблицы, затем используй new_document/add_table или Markdown → DOCX; PDF создавай через Typst. Не утверждай, что документ готов, пока нет проверок.
- DOCX: `python tools/docx_edit.py IN --images` показывает индексы рисунков.
  Операция `{"op":"resize_image","image":0,"width_cm":6}` меняет размеры inline/anchored DrawingML объектов, сохраняет пропорции при одном размере. Можно задать height_cm. Выход за область текста раздела и track changes для размеров запрещены.
- Перенос рисунка вместе с абзацем: существующая операция move с адресом #индекс. Плавающие якоря и текстовое обтекание требуют визуальной проверки. VML, диаграммы, SmartArt и изменение содержимого изображения этим API не поддерживаются.
- add_row сохраняет формат строки, но сбрасывает vMerge. gridSpan сохраняется: values адресует физические ячейки строки. Для образца с вложенной таблицей/рисунком инструмент отказывает, чтобы не дублировать объекты/ID. Для увеличения числа строк используй несколько операций add_row в одном пакете.
- PDF без исходника: `python tools/pdf_objects.py IN.pdf OUT.pdf --ops ops.json [--dry-run]`.
  Номера страниц page — с 1, после предыдущей операции. Координаты rect — [x0,y0,x1,y1] в пунктах.
  Операции: insert_image (file), insert_text (text, fontsize), insert_table (rows), rotate_page (angle=0/90/180/270), duplicate_page, delete_page.
  Вставки только на неповорачиваемую страницу в свободный прямоугольник; наложение на текст, изображения или векторы запрещено. Текст и таблицы не уменьшаются автоматически ради вмещения. Пути изображений — относительно ops.json.
- Пример пакета PDF: `[{"op":"insert_table","page":1,"rect":[50,140,540,350],"rows":[["Метрика","Значение"],["Выручка","120"]]}]`.
- Рост существующей таблицы в PDF, изменение сложной векторной фигуры и OCR требуют исходника/отдельного специализированного процесса. Не имитируй такую правку закрашиванием старого содержимого.
- DOCX/PDF редакторы сохраняют результат через временный соседний файл, проверяют его и атомарно публикуют. Ошибка сохраняет прежний результат и оригинал. Существующий отдельный выходной файл может обновляться; путь оригинала и его файловые алиасы запрещены.
- PDF text replace отказывает при нескольких строках, смешанных шрифтах/размерах/цветах, повороте и пересечении целей.
- Рендер Office/Typst/HTML выполняется в новой временной папке: старый PDF не считается успешным результатом. Неподдерживаемые расширения отклоняются.
- После доработок: `python tests/regression.py`, затем `python tests/validate.py --offline` (полная проверка без сетевой загрузки). Для стороннего научного PDF можно отдельно запускать validate.py без --offline.
- Область поддержки: DOCX/PDF; Excel и PowerPoint пока не реализованы.

Перенос объектов в track changes и клонирование таблиц с вложенными таблицами/рисунками запрещены: это предотвращает повтор DrawingML ID. Для перемещения рисунка используй обычный move без --track.

Для разнообразных регрессий: python tests/randomized.py --qa (нужны четыре исходных DOCX в out/randomized/external и attention.pdf в out/validation; источники перечислены в out/randomized/SOURCES.md), затем python tests/pdf_randomized.py. Seed фиксирован для воспроизводимости. Контактный лист учитывает поворот страницы PDF.
